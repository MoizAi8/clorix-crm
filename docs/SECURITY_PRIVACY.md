# Security & privacy release requirements
Threats: cross-tenant IDOR, auth/session theft, malicious input, abuse of public sandbox, leakage through export/search/cache/logs, duplicate writes, unsafe AI data transfer. Portfolio scope does not excuse privacy issues. Use synthetic data only on free hosted evaluation. Avoid real client lists, personal data imports and commercial usage.

- Mature auth, strong password policy (min 12, reasonable max, no truncation), library hash, httpOnly Secure SameSite cookies in production; CSRF/origin protections for mutations; no token storage in localStorage. Rate-limit login/register/invite/provisioning with atomic DB counters; generic errors. Rotate/revoke sessions through library. Enforce session expiration and active membership each request. No password recovery UI unless real secure workflow.
- Authorize all list/detail/update/archive/move/search/export/report operations. Use scoped composite FKs and DB RLS, FORCE RLS on tenant tables, runtime nonowner NOBYPASSRLS, no DDL. RLS and app checks; transaction-local context only; verify no-context denial, pooling isolation, invite privilege boundaries. Carefully separate auth bootstrap/provisioning from tenant access; no arbitrary SECURITY DEFINER SQL or migration role at runtime. Test direct runtime writes to other tenants.
- Validate with Zod, body size limits, text limits, allowlisted sort/filters, parameterized queries, escape notes/plain text, no raw HTML. Prevent XSS, CSRF, SSRF (no fetching arbitrary company URLs), CSV formula execution (`=`, `+`, `-`, `@`, tabs/CR incl leading whitespace; escape text fields before quoting); preserve numeric legitimate fields as typed values. No arbitrary file uploads. Cap imports/exports and avoid logging row content. No external messages or scraping.
- Public sandbox: explicit click + policy notice, trusted-IP hashed quotas, active-session reuse, bounded global count, TTL and row limits; fail closed on quota DB failure. No real data entry expected; warning before import, synthetic sample only. Cleanup expired sandbox tenant and guest identity safely; no bulk delete of private accounts. Restrict sandbox exports to its own data and team invite settings off. Log security events without personal content.
- Use dedicated DB and keys, TLS, separate migrator credentials. .env.local and all secrets ignored, no screenshots with secrets, no raw dumps. Audit staged and prior history; rotate leaked keys. Restrict production migrations and run backups/restore only as authorized. Never reuse other project resources. No telemetry exposing CRM fields. Public health minimal. Security headers/CSP appropriate to app and animations, frame-ancestors, referrer policy, MIME protection. Verify cookies and cache policy.
- Optional Gemini: do not send names, emails, phone numbers, customer notes, amounts, real CRM data or free-form questions to unpaid services. Use fixed fictional data only, separately gated eligible users; no external AI by default. Rules-based assistance independent. See AI_POLICY.md.

Release blockers: authentication bypass, any cross-tenant access, secret leakage, unauthorized exports, unsafe sandbox provisioning, broken core persistence, unhandled core error or false metrics. Record unresolved issues and fail release gate.
