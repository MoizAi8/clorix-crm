# Business rules and metrics
## Lifecycle
Lead statuses: New → Contacted → Qualified → Converted or Disqualified. Requalify disqualified lead explicitly; converted status terminal, link existing contact/deal. Qualification requires name and valid optional email/phone. Convert only qualified active lead; transaction locks lead, checks version, optionally reuses explicitly selected scoped company/contact, creates missing entities and one deal (open New stage), records conversion/activity. Idempotent retry returns same entity IDs; conflicting request returns 409. Never merge on name alone; normalize email for duplicate warning, allow explicit skip/create if meaningful. Converted lead may not be deleted if history exists.

Default deal stages: New, Qualified, Proposal, Negotiation, Closed Won, Closed Lost; stage kinds distinguish open/won/lost. Probabilities 10/30/60/80/100/0 as default configurable only in future. Drag/drop validates target and membership, preserves ordering via rank (transactional rebalance when needed) and optimistic version. Move to lost requires reason; won/lost set actual_closed_at on transition; reopen clears current actual_closed_at and keeps event history. No double counting current status after reopening. Amount edits for closed deals require reopen or explicit policy (MVP require reopen). Close date timezone display local, stored UTC. Log immutable stage events, actor and amount snapshot. Deal amount nonnegative and bounded, one currency per workspace. Archive removes record from active metrics; preserve historical events and distinguish reporting scope.

Tasks: due_at optional; overdue means open due_at before now; completion sets completed_at, reopen clears. Tasks and notes linked to permitted records; archived parent still visible in history, cannot create new linked activity unless restored. Member assignment must exist and be active. Activities are logs only, no email/call delivery. Notes render escaped plain text. Manual activity edit/delete only by permitted role per documented policy; system events immutable.

## Metric contract (current-state reporting, not accounting)
Open pipeline = sum amount of nonarchived open deals (as-of now, not date-filtered; label accordingly). Active leads = nonarchived New/Contacted/Qualified (all-time current). Won count and closed-won value = nonarchived currently won deals with actual_closed_at inside selected [start,end) UTC range computed from workspace timezone. Closed-won value is booked deal value, not collected cash or accounting revenue; UI label "Won deal value". Win rate = won/(won+lost) among currently closed nonarchived deals in selected range; zero denominator displays N/A. Weighted forecast = sum of current open amount × stage probability /100, rounded half-up to minor unit per deal; label estimate. Stage count/value = nonarchived deals grouped by current stage; show lost separately. Trend groups currently won values by month in workspace timezone; empty buckets zero; date range bounds explicit. Reopen removes deal from current closed metric; stage event history retained, historical point-in-time reports deferred. Upcoming/overdue task counts based on current state. No invented trends/percentages or retention metric without actual retention data.

Follow-up queue: open overdue tasks first, then tasks due next 7 days, then open deals/leads with no logged activity in 7 days (or never); deterministic sorting tie by ID. Show reason and source record, not an AI claim. Tests cover dates/DST, zero amounts, exact decimals, archived records, reopened deals, empty sets and concurrent transitions.
