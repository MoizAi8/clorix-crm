# Access without an invitation for portfolio evaluators
## Public sandbox (mandatory)
Public landing → Try live sandbox → explicit synthetic-only/expiry notice → server creates a new isolated demo identity and workspace using supported auth APIs and transactional seed. Session cookie is httpOnly/Secure/SameSite; account tied to that workspace, not a public shared password. Reuse active sandbox on repeated entry; refresh retains records. Exit/logout ends session, expiry prevents further access. Sandbox expires after 24 hours by default; no real data, no external sending, no inviting real members, no external AI except separately authorized fixed lab. Display expiration and label synthetic data. Do not promise a recovery mechanism for anonymous users. If browser clears cookies, old workspace inaccessible and expires.

Durable per-IP (keyed hash, trusted platform address only), per-session and global provisioning limits; DB atomic counters; conservative defaults in env; reject abuse with 429 and retry guidance. Do not rely on client cookies alone. Limit workspace records, import rows and request size; use bounded transactional cleanup of expired sandboxes plus documented admin script with dry-run. Quotas fail closed; public demo never uses elevated migration creds. Provisioning/cleanup use narrowly scoped vetted server capability (e.g. restricted function with fixed search_path and execute grants; test misuse). Never expose a general tenant bypass. No broad production deletion by automated test. If caps exhausted, honest unavailable state and contact/access alternative, not fake demo. No hidden account creation before explicit click.

## Private evaluation accounts
Email/password via mature auth, login/logout, password length/rate limit, secure session. Default `ALLOW_PUBLIC_SIGNUPS=false` for private accounts; owner-created one-time account invite or explicitly enable self-serve if abuse controls and email verification are actually implemented. Public evaluator needs no invite due to sandbox. Do not advertise password reset unless a real secure email workflow exists. Private evaluation accounts are for synthetic/non-confidential personal evaluation on Hobby, not client CRM. Do not log credentials. Owner can issue single-use expiring team invite copied manually, scoped to existing workspace, intended email if specified. Accept only after sign-in; no raw token storage, revoke and expire, membership insert atomic. Sandbox members/invites disabled by policy and UI clearly excludes them.

## Roles
Owner: all workspace record operations, membership management, settings, export, archive. Member: CRM records, own profile, view reports, export only if owner policy permits (default no), no workspace deletion/role editing. All records visible to authorized members within workspace for MVP (no per-record ACL). Nonmember: no data access. Prevent last-owner removal/demotion. Re-check membership on every request, session revocation after role/security changes. Guest is sandbox owner for CRM operations only, restricted for settings and invitations. See SECURITY_PRIVACY.
